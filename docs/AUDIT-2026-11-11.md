# Code audit, 2026-11-11

Baseline: `main` at `7682184` (version 0.5.1, 466 tests) plus the OpenAI
search/fetch JSON fix that was running on cachyos as
`reliquary:openai-json-fix-20261003` but had never been committed (now
`e326072`, 495 tests). Result: version 0.5.2, 849 tests.

Five read-only audits (auth and HTTP input, MCP tools and retrieval, storage
and concurrency, ingest/packaging/CI, and the separate corpus repository)
produced the findings. Fixes were written per area on separate branches, each
with a regression test that failed first, then merged and reviewed together
(see [Review](#review)). Nothing here was deployed: the running stack is
unchanged until the image is rebuilt.

No critical finding, no authentication bypass, and no way for a read token to
write was found in this repository.

## Findings and fixes

### Retrieval and the MCP surface

| Finding | Fix |
| --- | --- |
| OpenAI `search`/`fetch` error results carried `structuredContent` that violated the newly advertised `outputSchema`; the TypeScript MCP SDK rejects such results with -32602. | Errors return `isError` and the JSON as text, without `structuredContent`. |
| Near-duplicate suppression tokenised ASCII only, so distinct Japanese or Turkish notes sharing one Latin word collapsed into one result. | Exact check on normalised full text; Jaccard on Unicode word runs, with character pairs for unspaced scripts. |
| The exact-identifier lexical fallback scanned one page of 5,000 memories, imports included; the live store held 4,891. | Scan user-writes only, and grow the page when it comes back full. |
| A proposed correction and its original suppressed each other. | Corrections are exempt from deduplication and labelled `proposed` on the lean endpoint. |
| Cursor pages repeated and skipped records. | Every page slices one ranking of up to 100 hits per route, ordered by the selection key. |
| A backend outage looked like an empty result and a healthy status. | `backend_unavailable` when every route failed; `/status` and `reliquary_status` report `degraded`. |
| Tool exceptions returned raw exception text to the client. | `internal_error` plus an `error_id`; detail goes to the log. |
| `threshold` and explicit taxonomy filters were not applied to compiled pages before the cut; `nextCursor` could exceed the cursor cap. | Applied in the compiled search; `nextCursor` is null past the cap. |

### Caller metadata and governance

| Finding | Fix |
| --- | --- |
| Caller metadata could set system keys. A bad `blob_ref` made every search containing the record fail and the record undeletable; `import_record_id` made a user-write pose as an imported record and misdirected the next incremental import. | `app/metadata_policy.py` strips system-managed keys and reserved kinds on every write path. A bad `blob_ref` falls back to the record URL. Import ids are honoured only for imported records. |
| Search returned import ids that `fetch` could not resolve when the catalog lacked the record. | The memory id is used unless the catalog has the record. |
| Taxonomy values were stored verbatim (`Dev`), unreachable by the advertised `dev`. | Normalised to the catalog's slug form on write and on import. |
| Metrics labels came from caller-chosen tool names, unescaped and unbounded. | Unknown names are recorded as `unknown`; label values are escaped. |
| Audit log recorded the caller's claimed user and no page slug; upload instructions named the wrong tool on the Claude endpoint; untitled notes used the whole body as their title. | Fixed. |

### Authentication and HTTP input

| Finding | Fix |
| --- | --- |
| Request bodies were unbounded, including on the public `/oauth/*` routes. | 64 KiB on `/oauth/*`; inline-image headroom elsewhere; 413 beyond that. |
| The consent page displayed the redirect URI's netloc, so `https://claude.ai@evil.example/cb` read as claude.ai. | Userinfo, backslashes and control characters are rejected; the page shows the hostname, client id and resulting access level. |
| Scope parsing granted write to `read offline_access` and to static-token scopes such as `ro`. | OAuth: read-only when a read word is present without `write`. Static tokens: unrecognised words are read-only, with a warning. |
| Non-ASCII credentials and malformed MCP bodies returned 500. | 401 and JSON-RPC -32700. |
| `/v1` passthrough could leave the upstream prefix and forwarded cookies and proxy headers. | Path confinement and a header allowlist. |
| A read token could evict every other client's MCP session; rate limits were keyed on the token string. | Sessions and limits are keyed per credential (OAuth family, static label). |
| Access and refresh tokens were stored verbatim. | Stored as SHA-256 hashes; older state files are converted on first load. |

### Storage and durability

| Finding | Fix |
| --- | --- |
| `reliquary_delete_page` failed forever once the page's vector was gone. | An absent vector counts as deleted. |
| A failed `reliquary_compile_page` left a committed, current, unindexed revision. | The registry is rolled back; lint and needs-review report unindexed pages. |
| A page slug could shadow an imported or live record id. | New slugs that collide are refused. |
| No state write was fsynced; registry temp names were fixed and shared with the ingest CLI. | `persistence.atomic_write` (fsync, unique temp names) and a lock file on the registry. |
| The server could not start on embedded Qdrant with the compiled layer on. | The compiled store shares the embedded client. |
| Upload slots could be committed twice after a crash; expired uploads were reaped late; a malformed `pending_uploads.json` crashed startup. | Guarded, reaped on write tools, and validated on load. Lint reports orphan blobs. |
| Re-filing a page without `derived_from` or `title` wiped them; image writes did not mark pages stale. | Omitted fields are inherited; image writes fan out. |
| The retrieval-stats log grew without bound and was aggregated on the event loop. | Rotated at 16 MiB and aggregated in a thread. |

### Ingest, packaging and CI

| Finding | Fix |
| --- | --- |
| The documented ingest command duplicated the corpus on every re-run. | Incremental is the default. |
| Mem0 overwrote corpus dates at ingest, so the recency tiebreaker used import time. | Dates are kept as `source_updated_at` / `source_created_at` and preferred. |
| Slugs were ASCII-only (`günlük` became `g-nl-k`). | Unicode-aware, byte-identical for existing ASCII slugs. |
| One invalid byte disabled the whole catalog; `read_jsonl` did not check types. | Tolerant decoding; validation before any write. |
| The image user's uid was unpinned and `/data` directories were missing. | Pinned to 100:101 (the deployed ids), directories created. |
| Mem0 telemetry to PostHog was on by default. | Off in the image, compose and both CLIs. |
| CI installed only `httpx pytest` and publishing was not gated on tests. | CI installs the lock, audits both locks and builds the image; publish needs the tests; actions are pinned to commit SHAs. |
| anyio, urllib3 and certifi had open advisories. | anyio 4.14.2, urllib3 2.8.0, certifi 2026.10.18. |

## Review

The merged branch was reviewed by Codex (GPT 6.1 sol, high effort): the
built-in review and a focused pass on the merged result, then a verification
pass after each of six rounds of fixes. No critical finding. The last pass
found no new defect and agreed to the merge, with the shutdown limit listed
under [Left open](#left-open). The findings it raised, all fixed here:

| Finding | Fix |
| --- | --- |
| Upload cleanup inferred a slot's reference from the blob's aggregate count, so after a crash it could consume another image's reference and delete committed bytes. Later rounds found further ways for slot recovery to release a reference it did not own. | Each pending slot marks its own reference as an `upload:<id>` owner, and a reference changes only through that marker (`BlobStore.settle_owner`, which does nothing when the marker is absent). A commit records its user before writing a caption; caption deletes retire the caption's slot; when ownership is uncertain the bytes are kept and lint reports them. A model-based test drives sequences of uploads, commits, retries, expiries, deletes, restarts and storage or backend failures and checks after each step that no caption loses its bytes. |
| Verbatim OAuth mode returned the master bearer for a read grant. | Read grants always get a derived read token. |
| Compile rollback restored the registry without reconciling the index, and could erase a concurrent stale mark. | The index is read back and the result says whether it was confirmed; an invalidation counter keeps a page stale when its sources moved. |
| Staleness matching compared taxonomy literally, so legacy spellings (`Work Notes`, `g-nl-k`) no longer matched new slugs; explicit search filters did not round-trip. | Matching uses the current slug and the old ASCII slug; filters search both spellings. Match and mark happen under one registry lock. |
| Incremental ingest updated one copy of a record imported several times. | Every trusted copy is updated; the summary counts duplicates. Staleness marks survive an interrupted run. |
| MCP session ownership was recorded but not enforced. | Use and DELETE require the recorded owner and endpoint; sessions persisted without an owner are dropped at load. |
| The registry lock was taken on the event loop; cancellation released locks while a worker thread was still writing. | Registry mutations run in worker threads; compile, page delete, memory writes, image commit and image delete drain before releasing their locks. |
| Vault export could prune the last readable copy of an unreadable page. | Previous files are kept while the body cannot be read. |

## What an existing deployment will notice

- **Scopes.** An OAuth grant keeps write unless its stored scope contains a read
  word and no `write`. A static token with an unrecognised scope word (`rw`,
  `ro`) becomes read-only.
- **Token state.** `oauth_tokens.json` and `oauth_refresh_tokens.json` are
  rewritten with hashed keys on first start. Copy both aside before the first
  start: an older image must not run on the migrated files (PROJECT.md has the
  rollback procedure).
- **Sessions.** MCP sessions persisted before this version have no owner and
  are dropped at start; each client gets one 404 and re-initialises.
- **Uploads.** Pending upload slots add an `upload:<id>` owner to the blob
  sidecar. Before starting an older image, check that `pending_uploads.json`
  is empty. Slots left by the previous version are forgotten at start: an
  upload in flight across the upgrade answers `unknown_upload` and is
  repeated, and its bytes stay as an orphan that lint reports. Commit, upload
  POST and slot creation answer `state_write_failed` when the slot table
  cannot be written.
- **Verbatim OAuth mode.** Read-only grants receive a derived token instead of
  the master bearer.
- **Next incremental import.** Records that carry a date, or whose taxonomy is
  not already a slug, are rewritten and re-embedded once, as is every outdated
  duplicate copy of a record.
- **Ranking and pagination.** Order now includes the lexical and recency
  bonuses; page 1 asks Mem0 for 100 candidates per route.
- **Lint.** `--strict` now fails on current pages with no index entry and on
  orphan blobs.
- **New files.** `.lock` in the page registry directory,
  `.reliquary-export.json` in an exported vault, a rotated stats log.

## Left open

- A search filter that mixes a legacy spelling in one field with a slug in
  another matches only records stored with exactly that mix.
- An old ASCII slug of a non-ASCII value (`stra-e`) cannot be matched to its
  new slug (`strasse`) without the original spelling.
- At process shutdown a worker thread can outlive its cancelled task, so its
  lock is released before it finishes. A settling lookup that never returns is
  abandoned after a 5-second grace and applies nothing, but its thread can
  still delay process exit.
- On embedded Qdrant a settling lookup holds the exclusive store lock, so a
  hung lookup blocks writes there.
- Lookups by `slug` and `upload_id` filter on unindexed payload keys. A Qdrant
  server in strict mode needs payload indexes for them; without those the code
  keeps the reference and reports the index as unconfirmed.
- Duplicate copies of an import are brought up to date, not removed.
  Re-import into an empty collection to drop them.
- Boolean environment variables treat a blank value as false.
- Mem0 still overwrites the metadata keys `role`, `hash` and `data` on import.
