# Local service audit, 2026-09-06

Baseline: commit `e9af7d7`, version 0.5.1, 444 passing tests. The live Docker
image matched that commit. Existing untracked artwork was left untouched.

## Confirmed findings and fixes

| Finding | Fix |
| --- | --- |
| Live query `reliquary MCP architecture` placed 11 unrelated compiled pages before the first relevant raw memory. | Rank both layers by relevance, with a 0.05 preference for current syntheses on close matches. |
| Concurrent POSTs could both consume one upload slot, leaking bytes or references. Concurrent commits could create two captions backed by only one reference. | Claim each slot before awaiting and release it in `finally`; skip active slots during expiry cleanup. |
| A disconnected upload could be stored as a complete image. Expected size was not checked. Retrying an expired uploaded slot leaked its blob. | Reject incomplete/mismatched/expired bodies and reclaim expired slot references. Failed size checks leave the slot retryable. |
| Editing/deleting a source left dependent summaries marked current. | Mark dependent pages stale after successful memory updates, memory deletion and image deletion, including both old and new taxonomy on moves. |
| Revision construction mutated the previous revision before recording its timestamp/status. Repeated content hashes collapsed history metadata. | Copy the prior revision and match history metadata by occurrence. Existing historically incorrect metadata is not reconstructed. |
| Concurrent page filings created duplicate vectors for one slug. | Serialize page filing and deletion across registry and indexing operations. |
| Old refresh tokens lost replay protection immediately after rotation because retention used creation time. | Persist the consumption timestamp and retain the replay window from rotation, with backward-compatible loading. |
| Authorization codes and explicitly identified refresh requests were not bound to their original clients when dynamic registration was enabled. | Enforce the stored client identity. Legacy unpinned clients omitting client ID on refresh remain supported. |
| Image URL validation resolved DNS separately from the HTTP connection, allowing DNS rebinding. Invalid ports raised exceptions. | Resolve once, reject nonpublic answers, pin the connection IP on every redirect, preserve Host/TLS validation, and reject malformed URLs. |
| Incremental import used `get_all(user_id=...)`, rejected by installed Mem0 2.0.4, and did not request the full corpus. | Adapt to the installed signature and grow the requested result prefix until complete. |
| Docker pinned vulnerable `h2` 4.3.0, while uv selected different Mem0 and Uvicorn versions. | Update `h2` to 4.4.1 and align the direct runtime pins across installation paths. |
| Live blob/upload links lacked the public origin. | Set `RELIQUARY_PUBLIC_BASE_URL=https://reliquary.arda.tr` in the local deployment override. |

Regression coverage is in `tests/test_audit_regressions.py`, plus updated OAuth
tests. Failing regressions were run against the original implementation before
the fixes. Additional cases cover size retries, expiration during receive,
cleanup during a commit, redirect rejection and replay protection after restart.

### Existing public-ingress restriction

Cloudflare returns HTTP 403 for `/blobs/*` and `/favicon.ico`; the same signed
blob URL returns HTTP 200 at the origin. Public blob blocking matches the
intentional policy in [INGRESS.md](INGRESS.md), although favicon blocking is
stricter than that document's allowlist. Authenticated MCP image retrieval
works. The local deployment fixes the URL origin, but does not change remote
Cloudflare policy. Public signed downloads require a separate ingress change;
the user was asked whether to enable them.

## Deployment and rollback

Local image: `reliquary:local-audit-20260906`, built from this checkout. The
original image `ghcr.io/c0ze/reliquary:0.5.1` remains available. The Compose
override selects the local image and public URL; it does not change data mounts.
Connector state was copied to
`/home/arda/reliquary-deploy/backups/state-20260906/` before recreation, under a
private backup directory.

To roll back application code, from `/home/arda/reliquary-deploy` run:

```sh
docker compose -f docker-compose.yml up -d --no-deps --force-recreate app
```

This explicitly excludes the local override. Rename/remove the override before
subsequent default Compose commands if staying on the original image. Do not
restore an old OAuth state snapshot during ordinary rollback, since that could
resurrect revoked credentials. No corpus rewrite or public release is part of
this audit.

## Scope limits

This audit covers application code, installed dependency contracts, automated
tests and local/connector smoke checks. It is not a penetration test of the
external OAuth clients or Cloudflare infrastructure. The service still assumes
a single process and does not offer cross-store transactions across the
filesystem and Qdrant. No destructive crash injection or full corpus re-import
was performed against live user data.
